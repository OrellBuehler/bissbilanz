# Mobile parity audit, 2026-11-17

Android phone app versus iOS phone app, audited on `main` at `c0e1c402` (after v1.60.0, with #917–#920 merged). The audit was a code reading of both sides. Nothing was run on a device. Items marked **likely** were inferred and need a device check before they are fixed.

Path shorthand, all under `mobile/`:

- `A:` = `androidApp/src/androidMain/kotlin/com/bissbilanz/android/`
- `S:` = `shared/src/commonMain/kotlin/com/bissbilanz/`
- `I:` = `iosApp/Bissbilanz/`
- `P:` = `iosApp/PhoneShared/`

Severity: high = feature missing or data at risk, medium = partial, low = cosmetic. Effort: S, M, L.

Deliberately platform-specific, not gaps: on-device meal estimation and labelling with Apple Foundation Models, Visual Intelligence, Liquid Glass, Live Activity versus the ongoing fasting notification, native Sign in with Apple, lock-screen accessory widgets, CloudKit versus Android Auto Backup, the MCP / connect-an-assistant OAuth UI (web only).
